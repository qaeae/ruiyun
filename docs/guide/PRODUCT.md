# 产品说明书

> 面向：新同事、产品、测试、实施。
> 读完你应该能回答：**这个系统给谁用、挣钱在哪三块、一张单据怎么走完全程、哪些功能已经能用。**

---

## 1. 一句话定位

**智能化仓库平台**：为电商/品牌商家提供「仓储空间 + 代发货 + 物流代结算」的一体化履约服务。

不是"一个仓库管理系统"，而是**三方角色共用的履约平台**：

| 角色 | 在自己系统里做什么 | 在平台里得到什么 |
|------|------------------|-----------------|
| 商家 | 下单、看库存、对账 | 不用自建仓、不用自己谈快递、账单可逐笔核对 |
| 平台 | 招商、定价、结算、风控 | 仓租 + 操作费 + 运费差价 |
| 承运商 | 取号、揽收、回传轨迹 | 稳定单量、月结 |

## 2. 三类业务（收入与成本的来源）

| 业务 | 一句话 | 关键单据 | 主要表 |
|------|--------|---------|--------|
| **空间租赁** | 按面积/库位/时长收仓租，含超额与折扣阶梯 | 合同、价目表、额度 | `cs_contract` `cs_price_list` `cs_price_item` `cs_space_quota` `cs_rate_snapshot` |
| **代发货** | 商家订单进来，仓内拣货打包出库，平台收操作费 | 入库单 ASN、出库单 | `in_asn` `iv_sku` `iv_location` `out_order` `out_order_item` |
| **物流代结算** | 平台先与承运商结算，再与商家对账收款，赚差价 | 运单、对账单、结算批次 | `lg_shipment` `fn_rate_card` `fn_reconcile_bill` `fn_settle_batch` `ac_*` |

> **当前实现状态见 §5**：代发货（出库侧）与物流代结算已跑通；空间租赁只建了表结构。

## 3. 角色与权限

权限码形如 `域:对象:动作`（如 `outbound:order:dispatch`），共 38 个，按域分布：
`outbound 11` · `master 7` · `auth 6` · `stock 5` · `finance 4` · `logistics 2` · `ops 2` · `pricing 1`。

| 角色 | 典型权限 | 系统里能做的事 |
|------|---------|---------------|
| 平台运营 | `master:*` `finance:query` `pricing:*` | 维护商家/商品/仓库/承运商、看对账与结算 |
| 仓库主管 | `outbound:order:query` `stock:query` `ops:job:query` | 盯单量、查库存、看定时任务 |
| 拣货员 | `outbound:order:query` `outbound:order:pick` | 派发、拣货完成、缺货上报 |
| 复核/安全员 | `auth:approval:review` `outbound:order:load` | 复核双人流程、装车确认（不可逆动作） |
| 财务 | `finance:*` | 对账、确认、结算下发（**需双人复核**） |
| 商家（商家端） | 只读自身数据 | 查库存、查账单、看轨迹 |

两条硬规则：

1. **超管（`admin_flag=1`）视为拥有全部权限**；其他账号严格按权限码判定。
2. **权限快照在令牌里**——改授权后必须重新登录或刷新令牌才生效（这是"改了权限怎么没反应"的常见原因）。

## 4. 一条出库单的完整生命周期

```
商家下单/导入
      │  API-OUT-01 建单：校验禁入品类 → 预占库存(reserved) → 冻结运费
      ▼
   待接单 ──派发──▶ 拣货中 ──拣货完成──▶ 已复核 ──称重量方──▶ 已复核 ──打包──▶ 已打包
      │              │                                            │
      │              └─缺货上报─▶ 缺货待处理 ─恢复拣货─▶ 拣货中      └─(偏差>20% 拦停)
      │                                                                 │
      └────────────── 取消（按回滚矩阵）──────────────┐                 ▼
                                                      │            扫码交接
                                                      │                 ▼
                                                      │              待装车
                                                      │                 │ 装车确认（库存出账）
                                                      ▼                 ▼
                                                   已取消            已出库（终态，不可取消）
```

**九个状态**：`待接单` `拣货中` `缺货待处理` `已复核` `已打包` `待装车` `已出库` `已取消` `已拦截`

**三个终态**：`已出库`（货已出账）、`已取消`、`已拦截`。终态不可再流转。

### 4.1 取消回滚矩阵（不同时点，回滚的东西不一样）

| 取消时点 | 释放预占 | 库位分配归位 | 作废面单 | 记操作费 |
|---------|---------|------------|---------|---------|
| 待接单 | ✅ | — | ✅（未取号，直接作废） | ❌ |
| 拣货中 | ✅ | ✅ | ✅ | ❌ |
| 缺货待处理 | ✅（剩余） | ✅ | ✅ | ❌ |
| 已复核 / 已打包 | ✅ | ✅（回拣货位） | ✅ 并标记 | ❌ |
| 待装车 | ✅ | ✅（回拣货位） | ✅ 必须作废 | ✅ 按实际作业量 |
| **已出库** | **禁止** | — | — | — |

> 已出库只能走逆向流程（退货入库/拦截退回）。接口会返回 `20002` 并给出这句可读文案。

### 4.2 当日单 / 次日单（截单时间）

按**仓库**的 `cutoff_time` 判定：截单前建单为当日单，之后为次日单。
列表里 `isSameDay` 一眼可见——它决定承运商取号批次与运费价目（`mock`/生产价目可能不同档）。

### 4.3 两个不可逆动作（系统会二次确认）

| 动作 | 后果 |
|------|------|
| **装车确认** | 库存出账（实物、可用同步扣减），单据转终态，不可取消 |
| **异常拦截** | 单据转 `已拦截` 终态，回滚预占、释放冻结、作废面单 |

## 6. 核心业务规则（写代码前必须知道）

1. **库存三态**：`实物 = 可用 + 预留`。任何操作后都要成立，不成立即数据事故（有 4 条不变量守护）。
2. **两级账**：SKU 三态 与 库位实物合计 必须一致。只平一级 = 有人绕过接口改了库。
3. **预占而不是扣减**：建单只把 `可用 → 预留`，真正扣实物在**装车**（出账点）。
4. **运费先冻结后扣减**：建单按 `预估运费 × 1.1` 冻结；余额/冻结不足直接拒单（`20001`），**不做部分成功**。
5. **实拣必须等于应发**：不等就走「缺货上报」，由系统释放差额预占；不接受"少拣一点照发"。
6. **称重量方偏差 > 20%** 拦停（`20003`）——防止按体积重计费的运费被系统性做低。
7. **双人复核**：结算下发、库存调整等敏感动作必须"申请人 ≠ 复核人"。
8. **幂等**：所有写接口要求 `Idempotency-Key`；同键同体重放返回原结果，同键异体报 `10002`。
9. **客户隐私**：收件人姓名/电话/地址加密存储、接口只回掩码（`张*`、`139****0001`）。
10. **数据范围**：非超管只能看自己 `au_user_warehouse` 授权范围内的仓库。

## 7. 术语表

| 术语 | 含义 |
|------|------|
| ASN | Advance Shipping Notice，入库预告单 |
| 三态 | 实物 / 可用 / 预留（`physical` / `available` / `reserved`） |
| 两级账 | SKU 级三态账 + 库位级实物账，两级必须平 |
| 截单 | 仓库每日停止当日出库的时间点（`cutoff_time`） |
| 当日单/次日单 | 截单前/后建的单，影响取号批次与价目 |
| 出账 | 库存实物真正扣减（发生在装车确认） |
| 冻结 | 按预估费用锁定商家账户金额，实际扣减在对账/结算时发生 |
| 兜底扣减 | 商家账户不足时从保证金/授信兜底扣付 |
| 对账 | 平台账单 vs 承运商账单逐单比对，差异按 1 元/1%/20% 三档处理 |
| 结算批次 | 一次下发给承运商/商家的付款批次，需双人复核 |
| 幂等键 | `Idempotency-Key`，保证同一操作重试不会重复产生副作用 |
| 状态轨迹 | `pf_biz_status_log`，每次状态迁移一条，含操作人/设备/traceId |
| 不变量 | 库存恒等式，`POST /inventory/invariant-check` 一键校验 |
