# 智能仓储平台 · 前端

Vue 3 + TypeScript + Vite + Element Plus 后台管理台（仓库 PC 端 / 商家端）。

> **开工前必读**：`wms-platform/docs/frontend/W5-FRONTEND-KICKOFF.md`（接入契约、权限口径、页面清单、DoR/DoD）。
> 接口清单（自动生成）：`wms-platform/docs/frontend/api-contract.md`。
> 工程规范：`.agents/skills/admin-system-knowledge/`（R1–R12），已按本项目口径改写（见下）。

## 快速开始

```bash
pnpm install
pnpm dev          # http://localhost:5173（/api 代理到后端 8080）
```

| 命令 | 作用 |
|------|------|
| `pnpm dev` | 开发（含 `/api` 反向代理，避免本地 CORS 配置） |
| `pnpm build` | 类型检查（`vue-tsc --noEmit`）+ 生产构建 |
| `pnpm test` | 单元测试（vitest） |
| `pnpm check:standard` | **规范自检**（R1–R12 子集 + 本项目 F4 改写，违规即退出码 1） |
| `pnpm check:api` | **契约校验**：把 `src/models/*.ts` 里调用的接口与后端契约清单逐条比对（路径/动词写错即失败） |

## 与后端对接的三条硬约定（做错了会在生产出问题）

| # | 约定 | 实现位置 |
|:--:|------|---------|
| 1 | 成功码是 **`code === 0`**（不是 HTTP 200 / 不是 200） | `src/utils/request.ts` |
| 2 | 写接口自动带 `Idempotency-Key`，**同一业务动作重试复用同一个键** | `src/utils/idem.ts` + 请求拦截器 |
| 3 | **401 跳登录、403 只提示**（403 跳登录会让用户反复重登也解决不了） | `src/utils/request.ts` 响应拦截器 |

### 为什么第 2 条单独做成一个模块

"每次调用都新生成幂等键"是最容易犯、也最难发现的错误：本地不会超时重试，所以问题只在生产
网络抖动时出现（表现为**重复扣款/重复建单**）。本工程的做法是让调用方**没有机会写错**——
请求层用「方法 + URL + 负载指纹」作为动作标识，同一动作天然拿到同一个键；
业务成功后自动清除（下次点击视为新动作）。规则由 `src/utils/idem.spec.ts` 的 8 个用例守住。

## 目录结构

```
src/
├── models/        # 接口/类型/常量（Qo 入参 / Vo 出参），业务请求都从这里出（R2/R3）
│   ├── common.ts        # 分页、排序
│   ├── menu.ts          # 菜单与权限码（按分组，按权限过滤）
│   ├── auth.ts          # 登录/刷新/身份
│   ├── inventory.ts     # 库存三态、库位、流水、调整（调整走复核）
│   ├── approval.ts      # 双人复核（待办/我的申请/通过/驳回/撤回）
│   ├── finance.ts       # 对账/结算/兜底扣减/日终勾稽/垫付
│   ├── master.ts        # 商家/仓库/库区/库位/商品/箱规/设备
│   └── job.ts           # 定时任务（一览/历史/补跑/启停）
├── utils/
│   ├── request.ts  # ★ 接入契约唯一实现处（成功码/幂等键/401-403/409-429）
│   ├── idem.ts     # ★ 幂等键生成与复用（含单测）
│   └── mask.ts     # 写操作遮罩（R6）
├── stores/auth.ts  # 会话与权限快照（permissions / warehouseIds / adminFlag）
├── router/         # 路由 + 守卫（未登录→登录，无权限→403）
├── layouts/        # 基础布局（菜单分组 + 按权限过滤 + 空分组不显示）
└── views/          # 见下方页面清单
```

## 页面清单（16 个）

| 分组 | 页面 | 关键口径 |
|------|------|---------|
| 库存作业 | 库存查询 / 库存调整 | 三态可核对；调整**返回复核单号**而非"成功" |
| 复核 | 复核待办 / 我的申请 | 详情展示内容快照；**自己发起的单禁用通过/驳回** |
| 财务 | 对账单 / 结算批次 / 垫付台账 / 日终勾稽 / 兜底扣减 | 下发走复核；**「待接入」≠差异**；触发限额≠失败；"已扣过"要显示 |
| 主数据 | 主数据（商家/仓库库位/商品箱规 三个页签）/ 设备档案 | 层级串联选择；手机号只显示脱敏；设备停用会让 PDA 收到 403 |
| 运维 | 任务运维 | **「跳过」不是失败**；「执行中」长期不结束 = 卡死 |

## 已落地的关键界面口径（容易做错的地方）

| 页面 | 口径 | 为什么 |
|------|------|-------|
| 库存调整 | 提交后显示**复核单号**，不是"调整成功" | 否则用户以为库存已经改了 |
| 复核待办 | 详情**必须展示 `payloadJson` 内容快照**；**自己发起的单禁用**通过/驳回 | 复核人要判断"批的是哪一份内容"；自审等于没有复核 |
| 结算批次 | 下发后显示**复核单号**，不是"已付款" | 与库存调整同理：动钱的动作不能给"已完成"的错觉 |
| 日终勾稽 | **「待接入」单独一色**，不与「有差异」混排 | 否则运维把"没数据"当成"账不对"，天天白排查 |
| 垫付台账 | 触发限额提示为**"需人工审批"**，不是失败 | 限额是制度，不是错误 |
| 兜底扣减 | 必须展示「已扣过 / 本次可扣」 | 否则操作人以为漏扣，会手工再扣一次 |
| 任务运维 | 「跳过」用灰色、「失败」用红色 | 多实例下每周期约一半实例跳过，标红会造成告警疲劳 |
| 主数据 | 手机号只显示后端给的脱敏值 | 前端不接触明文 PII |

## 规范改写（与 `.agents/skills/` 原版的差异）

| 项 | 原版（外部项目） | 本工程 |
|----|----------------|--------|
| 成功码 | `code === 200` | **`code === 0`** |
| 请求标识 | 每次请求传 `apiCode` | **无 `apiCode`**；幂等键由 `request.ts` 统一生成 |
| 接口文档 | 根目录 `接口文档.md` | `wms-platform/docs/frontend/api-contract.md`（生成）+ `03-接口定义.md` |
| 自检脚本 | 原版 `check-standard.mjs` | `scripts/check-standard.mjs`（**已改写**：新增 3 条 F4 检查） |
| 新增校验 | —— | `scripts/check-api-paths.mjs`（**契约校验**，见下） |

### 自检脚本的四条新检查（都做过"探针双向验证"：写违规会红、删掉会绿）

1. 禁止 `code === 200` / `CODE_SUCCESS = 200`；
2. 禁止出现 `apiCode`；
3. 业务代码禁止手写 `Idempotency-Key`（否则各处实现不一致，重试复用必然漏）；
4. **模板禁止中文三元**（R7）。

> 第 4 条本轮抓出 **11 处**我自己写的违规（`row.status === '启用' ? '停用' : '启用'` 这类）。
> 全部改为调 `models` 里的 `toggleLabel()` / `jobEnabledLabel()` 等映射函数。

### 契约校验（本轮新增）

路径与动词写错**类型检查发现不了**（路径只是字符串），本地不联调就看不出来。`pnpm check:api` 把
`src/models/*.ts` 里实际调用的接口与后端契约清单逐条比对：

```
契约接口：87 个；前端调用：44 处
✅ 前端调用的路径与动词全部存在于后端契约中
```

探针验证：故意把 `/api/v1/jobs/{jobName}/run` 写成 `/api/v1/job/...` → **被检出**；恢复后绿。

## 环境相关的两个坑（实测，别再踩）

| 坑 | 现象 | 正解 |
|----|------|------|
| pnpm 12 拦截依赖构建脚本 | `pnpm install` 以 `ERR_PNPM_IGNORED_BUILDS` 结束 | 在 `pnpm-workspace.yaml` 写 **`allowBuilds`（映射形态）**；旧名 `onlyBuiltDependencies` 写了不报错但**不生效**，写成数组会报 `expected mapping start` |
| 构建产物 >500 kB 告警 | Element Plus 全量引入 | 一期可接受；后续按需引入或 `manualChunks` 拆分 |

1. 起后端（含一次性 MySQL 与 MOCK 支付通道）：见 `wms-platform/docs/frontend/W5-FRONTEND-KICKOFF.md` §六；

4. **还没做端到端联调**（见前置包 §〇 第 4 项）：本工程的验证止于"类型 + 构建 + 单测 + 自检 + 契约校验"。

## 联调结论（2026-10-14，真实 MySQL）

后端：`wms_integration` schema（独立库，未触碰既有库）；前端经 `pnpm dev` 的 `/api` 代理访问后端。

```bash
node scripts/e2e-smoke.mjs http://localhost:5173   # 28 步，期望全部通过
```

**联调确认的三条 ID/类型口径**（已写入 `models/` 注释与 `03` §1.1.1）：

| 类型 | 形态 | 前端约束 |
|------|------|---------|
| 雪花 ID | **字符串** | 必须透传，**禁止 `Number()` 转换**（19 位超 JS 安全整数，转了就错） |
| 计数/序号 | 数字 | 按数字处理 |
| 金额/数量 | 数字 | 展示时用 `formatQty`/`formatAmount` 格式化 |

**联调纠正的 3 处前端错误假设**（类型检查在改对之前发现不了）：

1. `GET /inventory/sku` 不是分页列表 → 改为"定位 SKU 看三态 + 两级账 + 库位 + 流水"；
2. ID 不是 number → 全部改为 `SnowflakeId`（string），表单由 `el-input-number` 改 `el-input`；
3. 商家"启用态"是 **「正常」**（不是「启用」，另有「黑名单」）→ 单独映射，否则按钮文案与实际状态相反。

> 联调同时验证了：发起人自批被拒、未处理差异禁止确认、下发走复核、403/401 区分、防用户名枚举、
> 幂等重放不重复入库、PII 只回脱敏值。**浏览器渲染与交互仍需人工点一遍**（脚本只覆盖接口与业务规则）。
